## 版本编号规则与历史例外

版本号是**十进制逐段进位**：`0.1.9` 的下一版是 `0.2.0`，任一段都不写两位数。
规则正文在 `AI-MAINTENANCE.md` §7（不随版本变，本表不重复）。

已交付的 `0.1.10` 是**唯一的历史例外**（末段误写成两位数）。按业主 2026-11-08 裁定：
该版已产出，**不重新打包、不回收**；它在序列上占用了 `0.2.0` 的位置，
因此下一版直接取 `0.2.1`，之后按进位规则递推 `0.2.1 → … → 0.2.9 → 0.3.0`。

## 验收数字去哪了

这里**不记录**测试数、覆盖率、PASS 数、基线重建张数。理由是它们每天都在变，抄进来就必然过期。
每轮当场的结论以 `reports/`、`coverage/` 和 `DELIVERY-REPORT.md` 对应版本章节为准；
`node scripts/handoff-check.mjs` 会打印仓库现状，用来跟文档对账。

## 维护方式

1. **每发一版加一行**，只写「版本 / 日期 / 一句话摘要 / 决策编号 / 产物目录」。
2. **不在这里写长文**：根因、取舍、验证细节属于 `DECISIONS.md`（append-only，编号用 `handoff-check.mjs` 查下一棒）。
3. **不回头改历史行**。某一版被淘汰就在 `BUILD-HISTORY.md` 记原因，本表保留原行供检索。
4. **不要把这些内容搬进 `AI-MAINTENANCE.md`**——那份只放不会过期的结构知识。
